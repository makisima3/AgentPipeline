# Остановка сервера из интерфейса

В **Настройки → Сервер трекера → Остановить сервер** доступны отмена и явное подтверждение. Команда выключает сервер для всех подключённых устройств и прерывает текущие задачи/чаты. Сохранённые результаты, отчёты и материалы остаются. Выполнявшиеся задачи переходят в бэклог со статусом «прервано» и сохраняют сессию; уже завершённые задачи и ожидающие вопросы не переписываются. Пайплайн сохраняется выключенным: после ручного запуска нужно самостоятельно вернуть задачи в работу и включить его.

Это отдельная операция от «Перезапустить трекер»: преемник не запускается, ожидающий перезапуск отменяется. Если запуск преемника уже начался, команда отклоняется: нужно дождаться новой страницы. Новый шаг первого знакомства и новые настройки подключения не требуются.

## Завершение и доступ

- `POST /api/shutdown` принимает `{"confirm":true}` и заголовок `X-AgentPipeline-Stop: <boot_id>` текущего `/api/state`. Origin, если передан, должен совпадать с HTTP Host. Нестандартный заголовок и отсутствие CORS/preflight исключают команду из сторонней формы/страницы. Устаревший boot_id и отсутствие подтверждения отклоняются.
- Модель доступа прежняя: любой пользователь доверенного интерфейса этого личного сервера имеет доступ к управлению. Сервер продолжает слушать только `127.0.0.1`; новых внешних адресов, ролей или паролей не добавлено. Android работает через уже настроенный USB/VPN/прокси.
- `Shutdown` в `server/main.py` закрывает приём новых мутаций, выключает пайплайн и закрывает затвор запусков в `runtime`. Останавливаются задачи, чаты, служебные генерации, импорт, Git и транспорт Telegram. Принятые HTTP-мутации и callback завершения получают время на завершение. Затем выполняется checkpoint SQLite.
- `runtime.popen/run` регистрируют процессы под общим замком; поздний запуск после команды запрещён. На Windows завершаются деревья через `taskkill /T`, на POSIX — отдельные группы процессов. Это не запуск произвольных команд из HTTP.
- `GET /api/shutdown` и SSE `shutdown` возвращают `running/stopping/stopped/error` и позволяют подтвердить завершение работы. `stopped` выставляется после завершения работы/процессов; через секунду закрывается HTTP, затем SQLite и дескриптор `server.lock`, процесс выходит. Секунда нужна для передачи подтверждения подключённым клиентам. При неполном завершении сервер остаётся с `error`, успех не заявляется; новые запуски запрещены.
- Отменённая/прерванная отправка Telegram сохраняет подтверждённые части и штатный статус ошибки/неопределённости; автоматически повторять неопределённую отправку нельзя.

## Закрытие страницы

После подтверждённого завершения инициирующая вкладка вызывает `window.close()`. Окна, открытые скриптом, обычно закрываются; обычную вкладку браузер может оставить. Тогда виден экран **«Сервер остановлен — вкладку можно закрыть»**, без фонового SSE и периодической синхронизации. Остальные подключённые вкладки показывают тот же экран, не закрываясь принудительно. Ограничение браузера описано в [Window.close](https://developer.mozilla.org/en-US/docs/Web/API/Window/close).

Повторные нажатия блокируются в UI, повторная принятая команда сервером идемпотентна в пределах запуска. HTTP-отказ при доступном сервере позволяет повторить. Потеря ответа вызывает проверку статуса; недоступность сети **не** считается успехом. После конечного ожидания показывается «Остановка не подтверждена» и кнопка ручной проверки подключения. Автоматический цикл переподключения прекращается; перезагрузка страницы после ручного старта возвращает интерфейс.

В APK 1.1 вызов `AgentPipelineAndroid.closeWindow()` только завершает Activity через [finishAndRemoveTask](https://developer.android.com/reference/android/app/Activity#finishAndRemoveTask()) и удаляет её из недавних. Серверные правила остаются общими. APK 1.0 получает новый экран с сервера, но не новый нативный мост: при невозможности закрытия остаётся экран, его можно закрыть системной «Назад». Настройки подключения и фоновое задание сохраняются. Нативная проверка результатов остаётся периодической и может встретить недоступный сервер после остановки.

## Изолированные проверки

`python -m unittest discover -s tests -p test_shutdown.py -v` поднимает настоящий `main.main` в отдельном процессе и временной папке. Проверяет отказ/подтверждение, простой, активные задачу/чат/служебные деревья, одновременные команды, ожидающий перезапуск, уже принятый импорт, закрытие порта, integrity_check, сохранность материалов и ручной запуск с прежней базой/портом. Модели и Telegram заменены безопасными Python-процессами, боевой сервер не используется.

`python tests/shutdown_demo.py` готовит отдельное демо и пишет порт в `output/playwright/task-47/demo.json`. Его процесс нужно остановить кнопкой или тестом; для повторного старта доступны `--reuse <sandbox> --port <порт>`. В копии нет реальной авторизации Telegram.

Через Playwright CLI откройте адрес демо и передайте содержимое `tests/shutdown_ui.js` в `run-code`: 390/1280 px, отмена, HTTP 503, потеря ответа, активная остановка, другая вкладка, настоящий запрет закрытия и отсутствие запросов в течение более 20 секунд. На новом демо `tests/shutdown_popup_ui.js` проверяет остановку простоя и настоящее закрытие окна, открытого через window.open. На Windows передавайте многострочный UTF-8 код как один аргумент напрямую node CLI, избегая преобразования строк оболочкой.

`python tests/android_shutdown_check.py --adb <adb>` проверяет установленный APK 1.1 только на эмуляторе: сохранённое подключение, результаты, кнопку, отмену, активную остановку, завершение Activity/удаление из недавних и недоступность HTTP. Для общей регрессии используйте отдельный `tests/android_demo.py`, `tests/android_check.py`, `tests/android_discussions_check.py`. Остановите свои демо и эмулятор после проверки. Физический телефон и естественный срок фонового расписания такими тестами не проверяются.
